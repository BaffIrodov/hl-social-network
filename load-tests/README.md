# Полное нагрузочное тестирование /user/search

Gatling 3.16.0, Java 21, Maven Wrapper. Сервис из IDEA и PostgreSQL в Docker
должны быть запущены, приложение — подключено к `social_network_load`.

## Одна команда

Из корня проекта в терминале PowerShell или CMD:

```powershell
.\load-tests\run.cmd
```

Команда сама выбирает JDK 21 из `JAVA_HOME` или установленных IDEA SDK в
`%USERPROFILE%\.jdks`. Если JDK не найден, задайте `JAVA_HOME` на свою установку JDK 21.

Перед запуском проверяются доступность API, наличие миллиона анкет в нагрузочной
базе и единственного индекса `users_pkey`. Для локального сервиса IDEA на Windows
также проверяется отсутствие Debug и `-XX:TieredStopAtLevel=1`.
Данные для стенда:
[генерация анкет](../docs/load-data.md).

Приложение запускайте через Run. Для конфигурации Spring Boot включите
`Disable launch optimization`, чтобы IDEA не ограничивала JIT-компиляцию.

## Что выполняется

1. Прогрев: один клиент в течение 30 секунд.
2. Уровни 1, 10, 100 и 1000 параллельных клиентов, по 120 секунд каждый.
3. Три повтора этой последовательности — всего 12 замеров.
4. Создание общего HTML-отчёта с таблицами, графиками latency, throughput и ошибок.

Перед каждым замером есть пауза 5 секунд. Следующий начинается после завершения
всех запросов предыдущего. Полный цикл занимает около 26 минут плюс время
ожидания оставшихся ответов; таймаут одного запроса — 30 секунд.

Запрос: `/user/search?first_name=Ив&second_name=Ив`.
Каждый клиент выполняет один запрос, после его завершения Gatling запускает
следующий. Пауз между запросами нет, соединения используются повторно.
Проверяются статус `200` и JSON-массив. Это конкурентность, а не заданный RPS.
Пул БД приложения сейчас ограничен 10 соединениями.

## Единый отчёт

Откройте в браузере:

```text
load-tests/target/benchmark/latest.html
```

Это один HTML-файл: графики работают без интернета и дополнительных файлов.
В нём есть:

- общая таблица по четырём уровням и отдельная таблица всех 12 замеров;
- средняя latency, p50, p95 и p99 успешных запросов;
- throughput всех и отдельно успешных запросов;
- доля ошибок и их распределение;
- параметры запуска, версия PostgreSQL, число анкет и список индексов.

Прогрев и паузы исключены из расчётов. Throughput рассчитывается по времени
соответствующих замеров, включая ожидание последних ответов. Перцентили считаются
по объединённым исходным latency повторов, методом ближайшего ранга.
Если все запросы завершились ошибкой, latency успешных запросов обозначается прочерком.

Каждый запуск также сохраняется в `target/benchmark/before-index-ДАТА-ВРЕМЯ/`:
`index.html` и исходные показатели повторов `measurements.csv`.
Стандартный подробный отчёт Gatling и его журнал остаются в `target/gatling`.
Для сравнения до и после индекса используйте одинаковые данные и параметры стенда.

## Параметры

Параметры необязательны, передаются той же команде:

| Параметр | По умолчанию | Значение |
|----------|--------------|----------|
| `duration` | `120` | Секунд подачи нагрузки на замер |
| `repeats` | `3` | Повторов последовательности уровней |
| `warmup` | `30` | Секунд прогрева |
| `cooldown` | `5` | Секунд паузы перед замером |
| `baseUrl` | `http://localhost:8880` | Адрес приложения |
| `firstName` | `Ив` | Префикс имени |
| `secondName` | `Ив` | Префикс фамилии |
| `stage` | `before-index` | Этап; `after-index` разрешает дополнительные индексы |

Быстрая проверка всей цепочки:

```powershell
.\load-tests\run.cmd "-Dduration=2" "-Dwarmup=1" "-Dcooldown=0" "-Drepeats=1"
```

Эти короткие результаты нужны для проверки настройки; для итоговых измерений
используйте обычный полный запуск. Индекс добавляется отдельным этапом.

Для запуска из Maven Runner IDEA выберите JDK 21 и выполните `gatling:test`
в Maven-проекте `load-tests`. Проверка расчётов отчёта: `mvnw.cmd test` из этой папки.
