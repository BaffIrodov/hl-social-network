# Социальная сеть

Приложение для регистрации, входа, просмотра и поиска анкет.

Java 21, Spring Boot 4.1.1, PostgreSQL 17, Spring JDBC и Liquibase.

## Запуск в Docker

Установите и запустите Docker с Compose v2.
Команды выполняются из корневой папки проекта:

```shell
docker compose up --build -d
docker compose logs -f app
```

Дождитесь сообщения `Started SocialNetworkApplication`.
Приложение доступно по адресу `http://localhost:8880`.
Ctrl+C завершает просмотр логов, приложение продолжает работать.

После проверки остановите контейнеры:

```shell
docker compose down
```

Данные БД сохранятся.

Подробная инструкция: [Локальный запуск](docs/local-startup.md).

Другие варианты:

- [Приложение на компьютере, PostgreSQL в Docker](docs/local-startup-java.md)
- [Запуск без Docker](docs/local-startup-postgres.md)

## Проверка через Postman

Импортируйте [коллекцию](postman/social-network.postman_collection.json).
На вкладке **Variables** проверьте `base_url=http://localhost:8880`.

В коллекции две папки по три запроса и отдельный запрос поиска анкет:

- **01 — Ручная проверка:** ID после регистрации переносится в следующие запросы вручную.
- **02 — Автоматическая подстановка переменных:** ID и токен сохраняются автоматически.

Выполняйте запросы по порядку: регистрация → вход → получение анкеты.
Через Collection Runner запускайте только автоматическую папку.

## API

| Метод                 | Назначение                    |
|-----------------------|-------------------------------|
| `POST /user/register` | Регистрация и создание анкеты |
| `POST /login`         | Вход и получение токена       |
| `GET /user/get/{id}`  | Получение анкеты              |
| `GET /user/search`   | Поиск по имени и фамилии      |

Все методы доступны без `Authorization`. Успешные ответы возвращают код `200`.
Регистрация возвращает ID пользователя. Токен выдаётся при входе и пока не используется
в запросах к этим методам.

### Регистрация

`POST /user/register`

```json
{
  "first_name": "Иван",
  "second_name": "Иванов",
  "birthdate": "1995-05-20",
  "gender": "MALE",
  "biography": "Java, музыка",
  "city": "Москва",
  "password": "ExamplePassword123!"
}
```

Ответ:

```json
{"user_id": "1"}
```

### Вход

`POST /login`

```json
{"id": "1", "password": "ExamplePassword123!"}
```

Ответ:

```json
{"token": "e4d2e6b0-cde2-42c5-aac3-0b8316f21e58"}
```

### Получение анкеты

`GET /user/get/1`

Ответ:

```json
{
  "id": "1",
  "first_name": "Иван",
  "second_name": "Иванов",
  "birthdate": "1995-05-20",
  "gender": "MALE",
  "biography": "Java, музыка",
  "city": "Москва"
}
```

### Поиск анкет

`GET /user/search?first_name=Ив&second_name=Ив`

Оба параметра обязательны: непустые префиксы до 100 символов.
Пробелы по краям удаляются. Поиск учитывает регистр и одновременно проверяет
начало имени и фамилии. Символы `%`, `_` и `!` во вводе считаются обычным текстом.

Ответ — массив анкет в том же формате, что у `GET /user/get/{id}`,
отсортированный по числовому ID по возрастанию. Если совпадений нет, возвращается
`200` и `[]`. Пагинации и ограничения количества результатов пока нет.

Параметр фамилии называется `second_name`, как и поле анкеты.
В исходной спецификации OTUS для поиска используется другое название — `last_name`.

Контракт API: [openapi.json](docs/openapi.json).
Исходная спецификация: [otus-openapi.original.json](docs/otus-openapi.original.json).

## Валидация и ошибки

При регистрации действуют следующие правила:

| Поле          | Обязательно | Ограничения                                            |
|---------------|-------------|--------------------------------------------------------|
| `first_name`  | Да          | Непустой текст до 100 символов, не только пробелы      |
| `second_name` | Да          | Непустой текст до 100 символов, не только пробелы      |
| `birthdate`   | Да          | Дата в формате `YYYY-MM-DD`, не позже сегодняшнего дня |
| `gender`      | Нет         | `MALE`, `FEMALE` или `UNSPECIFIED`                     |
| `biography`   | Нет         | Текст до 2000 символов                                 |
| `city`        | Нет         | Текст до 100 символов                                  |
| `password`    | Да          | От 12 до 40 символов, без пробельных символов          |

Если `gender` отсутствует или равен `null`, используется `UNSPECIFIED`.

В пароле разрешены английские буквы (`A–Z`, `a–z`), цифры (`0–9`)
и печатные спецсимволы ASCII, например `!@#$%`.
Пробелы, табуляция и переносы строк запрещены.

Пробелы по краям имени, фамилии, интересов и города удаляются.
Пустые интересы и город возвращаются как `null`.
Неизвестные поля JSON отклоняются с кодом `400`.

ID назначается автоматически при регистрации.
Для входа и получения анкеты используется его строковое представление:
число от 1 до 2147483647 без ведущих нулей, знака и пробелов.

| Код   | Причина                                 |
|-------|-----------------------------------------|
| `400` | Некорректный запрос или неверный пароль |
| `404` | Пользователь или адрес API не найден    |
| `500` | Внутренняя ошибка сервера               |
| `503` | База данных недоступна                  |

Пример ошибки:

```json
{
  "message": "Пароль не должен содержать пробельные символы",
  "request_id": "761a9817-9c63-4b48-9373-d2d40f46cb41",
  "errors": [
    {"field": "password", "message": "Пароль не должен содержать пробельные символы"}
  ]
}
```

В ответах есть заголовок `X-Request-Id`. В ошибках тот же ID передаётся в `request_id`.

## Хранение данных

- `users` — анкеты пользователей.
- `user_credentials` — пароли, хешированные с помощью Argon2id.
- `user_sessions` — SHA-256-хеши токенов и сроки действия сессий.

Регистрация сохраняет анкету и пароль одной транзакцией.
В таблицах приложения используются только индексы первичных ключей.
Миграции применяются автоматически при запуске.

Миллион анкет для будущих нагрузочных тестов генерируется в отдельной базе
`social_network_load`: [подготовка данных](docs/load-data.md).
Имена и фамилии равновероятно выбираются из [словаря](data/profile-names.json),
даты рождения — случайные, возраст от 20 до 50 лет включительно.
Для нагрузочных тестов выбран Gatling; на этом этапе дополнительные индексы ещё не создаются.

Токен — UUIDv4. Срок действия по умолчанию — 6 часов, настройка — `TOKEN_TTL`.

Для запуска тестов нужен JDK 21.

```shell
./mvnw test
```
